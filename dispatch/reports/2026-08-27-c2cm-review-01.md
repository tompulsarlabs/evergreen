## Findings

### 1. P0 — `src/types.ts:14,40` — Visibility is metadata, not permission enforcement

`visibility` is optional and therefore implicitly publishes all 42 legacy records. `src/components/ClientCard.tsx:181-271` merely adds an NDA badge before rendering raw name, tagline, location and leadership. `src/components/DetailDrawer.tsx:85-132` ignores visibility and exposes every populated field. `api/chat.ts:7-24` sends all raw records to the model, while `src/App.tsx:3-11` embeds the same JSON in the browser bundle. `logo_only` has no implementation or logo field.

**Proposed fix:** Make publication policy required and deny-by-default. Generate a central, validated public projection before data reaches the browser or model, with explicit discriminated shapes for public, logo-only and anonymized records. Keep protected source fields out of client artifacts entirely.

**Required tests:** Use sentinel secret names, CEOs, locations and investors for each visibility mode; assert they are absent from cards, drawer, search indexes, built public data and the model prompt.

### 2. P1 — `src/App.tsx:339-352` — Filter choices use stale pre-reset Sets

Each handler calls `onReset()` and then toggles values against Sets captured before that reset. React batches the setters. From an empty state, Europe issues independent `{United Kingdom}` and `{Continental Europe}` updates, so the latter wins: the chooser advertises 32 European clients but shows only 18, omitting all 14 UK clients. Switching or reselecting countries/industries can retain the old value or clear the requested value.

**Proposed fix:** Replace target Sets atomically rather than toggling: assign `new Set(CONTINENT_TO_REGIONS[c])` for continents and singleton Sets for country/industry while explicitly clearing the other dimensions.

**Required tests:** Cover Europe, switching values, reselecting the same value and selecting after a different filter dimension.

### 3. P1 — `src/App.tsx:73-79,875-879` — “View all 43 clients” displays no clients

`selectAll` clears all state. That makes `hasEngaged` false, so `src/App.tsx:388-415` renders `EmptyMatrix`. The “All” tile at `src/App.tsx:1010-1014` therefore cannot show the portfolio or demonstrate featured-first ordering.

**Proposed fix:** Introduce an explicit view mode such as `idle | filtered | concierge | all`. Split “show all” from “clear/reset” and render the matrix for `all`.

**Required tests:** Click “All” and assert 43 production-eligible cards render, featured cards precede others, and Clear returns to the intended idle state.

### 4. P1 — `src/App.tsx:472-486` — “Ask the portfolio concierge” is a dead CTA

The button only scrolls to `#card-view`. The latest commit removed the sticky `ChatBox` from that section; the sole chat is inside the conditionally mounted hero modal at `src/App.tsx:743-793`. Users land on cards or an empty invitation with no concierge control.

**Proposed fix:** Hoist the concierge modal state into `App` and have both CTA locations open and focus the same dialog, or restore a real concierge target at `#card-view`.

**Required tests:** Click the closing CTA and assert that a labelled concierge dialog and focused input appear.

### 5. P1 — `src/App.tsx:460-471` — The primary “Book” route is knowingly not production-ready

The CTA promises “Book a 20-min brief” but opens a `mailto:` using the address the PR itself identifies as a placeholder. It neither books a time nor provides a browser fallback if no mail client is configured.

**Proposed fix:** Configure a verified production inbox or scheduling URL through deployment configuration, align the action label with its actual behavior, and provide a visible fallback contact route.

**Required tests:** Assert the production destination and accessible link label; add an environment/configuration check that rejects placeholder destinations.

### 6. P1 — `src/App.tsx:51-59` — Concierge results are ANDed with stale manual or URL filters

LLM citations are intersected with every active industry, region, stage, country and search filter. For example, landing on `?lens=fintech` and asking for healthcare clients produces valid healthcare citations but zero cards.

**Proposed fix:** Define explicit interaction semantics. Prefer making a new concierge query replace manual/lens state, or expose the intersection as user-editable filters instead of silently returning zero.

**Required tests:** Start from a lens/manual filter, stream citations from another sector, and assert the cited cards appear under the chosen mode.

### 7. P1 — `src/clients.json:818-837` — A demo fixture is shipped as a confirmed engagement

The added “Confidential Series B FinTech” record is explicitly described as a placeholder, yet it enters production statistics, filters and the model corpus. It alone changes the dataset from 42 to the advertised 43 entries and Fintech from six to the test-plan claim of seven. `src/App.tsx:318-323` calls all 43 “active engagements,” although only eight records have non-null `engagement`, including this demo.

**Proposed fix:** Move the placeholder to test/story fixtures. Model production status explicitly and derive customer/engagement counts solely from approved production records.

**Required tests:** Reject demo fixtures from production data, statistics, filtering and the API prompt; assert separately defined client and active-engagement counts.

### 8. P2 — `src/components/ChatBox.tsx:30-45` — Markdown bold text is an unsafe identifier protocol

Every `**bold**` span is treated as a client name, then `src/App.tsx:49-66` applies bidirectional substring matching. A citation of `**Zalando**` matches both “Zalando SE” and “Tradebyte (A Zalando Company).” Bold headings can also become citations. The subsequent featured/source-order sort discards the response order despite comments saying citation order informs the grid.

**Proposed fix:** Return validated stable client IDs as structured metadata separate from display prose. Match exact IDs and define whether concierge relevance or featured status controls result ordering.

**Required tests:** Cover Zalando/Tradebyte, legal-name aliases, diacritics, unmatched bold text, duplicate citations and relevance ordering.

### 9. P2 — `src/App.tsx:90-103` — Partial lens matching is ambiguous and order-dependent

The code selects the first sorted industry containing the supplied fragment. `?lens=tech` matches both “Deep Tech & Semiconductors” and “Fintech & Payments” but silently chooses the former. Taxonomy or sort changes can alter existing prospect links; unknown values silently fall back to the idle view.

**Proposed fix:** Publish stable lens slugs with exact normalized lookup. If partial matching remains, accept it only when exactly one result exists and visibly report invalid or ambiguous values.

**Required tests:** Cover exact, case/whitespace-normalized, unknown, blank and ambiguous lenses.

### 10. P2 — `src/App.tsx:14-17,528-595` — Existing search, stage and refinement capabilities became unreachable

After removing `FilterBar`, no UI calls `setSearch` or `setSelectedStages`; the chooser at `src/App.tsx:839-1047` only offers continent, country, industry and All. The “refine+reset” status strip has inert chips and only a Clear button. This silent regression is outside the six stated decisions and contradicts `README.md:7-9`.

**Proposed fix:** Restore search, stage and result-refinement controls, or explicitly approve the capability removal and delete the dead state/documentation.

**Required tests:** Exercise search by client/CEO/HQ, stage selection, refinement from active results and reset.

### 11. P2 — `src/components/ClientCard.tsx:227-262` — “Outcomes” neither cover the portfolio nor contain outcomes

Only eight of 43 records have services/outcome fields, one being the demo, so 35 cards remain as shallow as before and can still be selected by the LLM. No record exercises `outcomeMetric`. Values such as `src/clients.json:230,252,313,356` describe hiring scope or service capability rather than achieved results. The “full profile” at `src/components/DetailDrawer.tsx:102-134` omits the new service/outcome fields entirely.

**Proposed fix:** Either populate permission-cleared, evidenced results for every card eligible for substantive output, or rename the data/UI to `engagementScope` and avoid outcome claims. Suppress uncurated cards from any path promising substantive output.

**Required tests:** Enforce approved enrichment coverage and cover metric-only, qualitative-only, combined and absent states in both card and drawer.

### 12. P2 — `src/App.tsx:11` — The data model is asserted rather than validated

`clientsJson as Client[]` bypasses checking of imported data. This already hides a mismatch: `src/types.ts:24` requires a string CEO while the anonymized record supplies `null`. At `src/components/ClientCard.tsx:249-251`, unknown service slugs are silently dropped. The `SERVICE_BY_SLUG` cast at `src/types.ts:105-107` can likewise claim a complete Record when an entry is missing.

**Proposed fix:** Parse the dataset through a runtime/build-time schema covering required fields, nullable values, enum membership, service uniqueness and visibility. Fail the build on invalid or unknown values rather than omitting them.

**Required tests:** Validate the complete production JSON plus fixtures for unknown services, invalid visibility/stage/region, duplicate slugs and nullable leadership.

### 13. P2 — `src/components/ChatBox.tsx:81` — Documented launch modes cannot run the promoted AI path

Chat calls `/api/chat`, but `README.md:33-49` documents opening `dist/index.html` via `file://` or running plain Vite. Neither serves the Vercel edge function. The added `.claude/launch.json:5-8` also launches only `npm run dev`. The required API key and supported full-stack runtime are undocumented.

**Proposed fix:** Provide and document a supported full-stack development/production command, configure a Vite proxy or mock where appropriate, and degrade gracefully to working browse controls when the backend is unavailable.

**Required tests:** Smoke-test every documented launch mode and verify chat success plus its unavailable-backend fallback.

### 14. P1 — `package.json:6-10` — None of the six decisions has an automated regression gate

There is no test script, test dependency, test file or GitHub Actions workflow/status. The manual PR checklist is already stale: it expects featured cards on an unengaged scroll and a sticky ChatBox that the current head removed.

**Proposed fix:** Add Vitest/React Testing Library for state, data and rendering behavior; Playwright for modal/CTA/lens journeys; and a required CI workflow running schema validation, tests, build and lint.

**Minimum gate:** Include every scenario named above, stable featured sorting without source mutation, approved CTA copy/actions, visibility sanitization through the API boundary and production-data assertions.
