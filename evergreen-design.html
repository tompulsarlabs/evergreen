Evergreen

A self-learning daily loop that keeps the tompulsarlabs contribution graph green — by getting real work shipped first, and guaranteeing the floor with a genuine journal commit when it isn't.

Design doc · 2026-08-22 · source at ~/Build/evergreen/DESIGN.md

Stance: no empty commits, no backdating, no synthetic noise. The failsafe commit is a real daily engineering journal. The system makes you ship — it doesn't fake it.

§2 · Architecture

One repo is the system

A public repo, tompulsarlabs/evergreen, is simultaneously the config, the memory, the guaranteed-green floor, and the version history:

evergreen/
├── config.yml        # watchlist repos, cutoffs, timezone, notification prefs
├── playbook.md       # the agent's own instructions — the learning loop edits THIS
├── state.json        # streak, last-green date, per-day outcome log
├── journal/
│   └── 2026-08-22.md # one entry per day: candidates, outcome, streak
└── CHANGELOG.md      # playbook revisions, tagged v1, v2, …

The loop runs as Claude Code cloud scheduled agents, so it works while the Mac sleeps. Three daily runs form the escalation ladder:

09:00

Scout

Auto-sync the watchlist from gh api user/repos (forks and archived excluded), honoring manual excludes in config.yml — "all projects" never depends on a hand-curated list. Then enumerate real shippable candidates: PRs one review from merge, assigned issues, stale branches, yesterday's carry-over. Draft today's journal entry. Quiet.

18:00

Check + nudge

Query today's contributions. Green → log silently. Grey → one push notification with the single most concrete candidate: "Grey so far. sybil #12 is one review from merge."

22:30

Failsafe + verify

Still grey → finalize the journal entry (findings, outcome, streak, tomorrow's top candidate), commit to main, push. Then re-query the API until today ≥ 1 — a failed verification alerts loudly the same night, catching email/branch/visibility misconfig immediately.

The ladder prefers real work by construction: 13.5 hours of runway between scout and failsafe, and every nudge points at a concrete next action, not a generic reminder.

Attribution note: the failsafe commit runs in the cloud sandbox, where this Mac's git config doesn't exist — inheriting environment config there is exactly the silent-grey email failure from rule 2. Author identity is explicit per commit: pass author/email in the commit command, or commit via GitHub's Contents API, which attributes to the token owner when author is omitted (confirm against the REST docs in Phase 1).

"Green" is defined by the authoritative query — contributionsCollection counts commits, PRs, issues, and reviews, exactly matching the graph. Because reviews count, the scout treats "review that open PR" as a first-class candidate — often the cheapest real contribution of the day.

query($login: String!, $from: DateTime!, $to: DateTime!) {
  user(login: $login) {
    contributionsCollection(from: $from, to: $to) {
      contributionCalendar {
        weeks { contributionDays { date contributionCount } }
      }
      restrictedContributionsCount   # private-repo activity
    }
  }
}

from/to span today 00:00–23:59 with the Berlin offset, so "today" means the same thing to the checker and to the graph.

§3 · Self-learning loop

The git history is the learning record

A weekly retro run (Sunday 10:00) reads the last 7–30 days of outcomes in state.json — how often the failsafe fired, which nudges converted into real commits within four hours, which repos actually produce shipped work — then makes one or two adjustments by editing playbook.md and config.yml. The next day's runs read the updated playbook, so behavior changes take effect immediately. Every change is a readable, revertible diff:

journal: 2026-08-22 — grey at 22:30, failsafe fired (streak 12)
learn:   shift nudge 18:00 → 17:00 — 3 of 4 failsafe days had
         no activity after 18:00                    (tag: v3)
config:  add tompulsarlabs/sybil to watchlist
scout:   2026-08-23 — 3 candidates, top: sybil #12 needs review

Commit-message prefixes plus a version tag on every playbook revision satisfy the clear-history and version-tracking requirements with no extra machinery.

Guardrail: the retro may tune timing, wording, and ranking. It may not touch the counting rules (§1), the verification step, or the no-synthetic-commits stance — those sections of the playbook are marked immutable, and changing them requires a human commit.

§4 · Prerequisites

Current blockers

Blocking

The gh token for tompulsarlabs on this Mac is expired. Run ! gh auth login in the session — it's interactive, so it needs you. Everything in Phase 0 hangs off this.

  1. Re-authenticate gh (above).
  2. Verify the commit email. After auth: gh api user/emails, then set the state repo's user.email to a connected address. The session default tom@tomgreen.ai may not be on the tompulsarlabs account — this would silently zero the graph.
  3. Give the cloud agents GitHub access. The routines run in Claude's cloud: either the Claude GitHub connector covering evergreen (plus read on watchlist repos), or a fine-grained PAT (contents: write on evergreen only).
  4. Decide repo visibility. Public evergreen (recommended), or private + "Private contributions" toggle.
  5. Confirm the timezone anchor. The Mac says Europe/Berlin.
